# Riverpark Document Registry (DAR) — Mockup

ระบบขอขึ้นทะเบียนและเปลี่ยนแปลงเอกสารตามมาตรฐาน ISO 9001:2015
**เป็น Mockup เท่านั้น — ไม่มีการเชื่อมต่อฐานข้อมูลหรือ API ใด ๆ** ข้อมูลทั้งหมดเก็บใน `localStorage` ของเบราว์เซอร์

---

## วิธีรัน

```bash
npm install
npm run dev          # → http://localhost:8080
```

หรือไม่ต้องติดตั้งอะไรเลย:

```bash
npx serve -l 8080
```

> แนะนำให้เปิดผ่าน `http://localhost` ไม่ใช่ดับเบิลคลิกไฟล์ เพราะโหมด `file://`
> อาจทำให้ CDN / canvas ลายเซ็นทำงานไม่ครบ

## บัญชีตัวอย่าง (Demo accounts)

หน้า Login มีการ์ดให้คลิกเข้าได้ทันที หรือพิมพ์เองก็ได้ — **รหัสผ่านใดก็ได้**

| Username | ผู้ใช้ | บทบาท | สิทธิ์ |
|---|---|---|---|
| `userA` | นาย A · สมชาย ใจดี | **Requester** ผู้จัดทำ | Create · Draft · Preview · Send · Edit |
| `userB` | นาย B · ประเสริฐ วงศ์ทอง | **Approver** ผู้อนุมัติ | ดูเอกสาร · Approve · Reject · Return |
| `userC` | นาย C · ปรีชา แสงจันทร์ | **Stakeholder** ผู้เกี่ยวข้อง | ดูเอกสาร · Sign |
| `userD` | นาย D · วิชัย ธนกิจ | **QC** แผนกควบคุมคุณภาพ | ดูเอกสาร · Register · Return |

สลับบัญชีเร็ว ๆ ได้จากปุ่มชื่อผู้ใช้มุมขวาบน → เลือกบัญชีอื่น

## Workflow (ตาม Flow chart)

```
DRAFT ─Send─► PENDING_APPROVAL ─Approve─► PENDING_SIGN ─เซ็นครบ─► SENT_TO_QC ─Register─► REGISTERED
  ▲                │  │                        │                      │
  │                │  └─Reject─► REJECTED      └─หมดอายุ 14 วัน─► EXPIRED_RETURNED
  │                │                                                  │        │
  └──Edit & Send───┴─Return──► RETURNED ◄──────QC Return──────────────┴────────┘
```

| สถานะ | ความหมาย | ผู้ถือเอกสาร |
|---|---|---|
| `DRAFT` | ฉบับร่าง | Requester |
| `PENDING_APPROVAL` | รอตรวจสอบ | Approver |
| `RETURNED` | ส่งกลับให้แก้ไข | Requester |
| `REJECTED` | ไม่อนุมัติ · ปิดคำขอ | — |
| `PENDING_SIGN` | รอผู้เกี่ยวข้องลงนามให้ครบ | Stakeholders |
| `SENT_TO_QC` | ลงนามครบ · รอ QC ขึ้นทะเบียน | QC |
| `REGISTERED` | ขึ้นทะเบียนสมบูรณ์ | — |
| `EXPIRED_RETURNED` | หมดอายุก่อนลงนามครบ · ระบบส่งกลับ | Requester |

## สคริปต์เดโม 5 นาที

1. **Login `userA`** → หน้า *มุมมองผู้จัดทำ*
2. กด **สร้างเอกสาร DAR** → กรอกส่วนที่ 1–4 → **แนบไฟล์ PDF/รูปจริง** ในส่วนที่ 4.1 → **เซ็นชื่อในส่วนที่ 5** → เลือกผู้เกี่ยวข้องในส่วนที่ 5.2 → กด **ส่งตรวจสอบ**
3. ระบบพาไปหน้าเอกสาร — **PDF 2 หน้าที่สร้างจากข้อมูลที่กรอกจริง** พร้อมลายเซ็นที่เพิ่งวาด · แท็บ **ไฟล์แนบ** เปิดไฟล์ที่อัปโหลดได้จริง
4. สลับเป็น **`userB`** → กระดิ่งเด้ง → เปิดเอกสาร → **อนุมัติ** (หรือ **ส่งกลับไปแก้ไข**)
5. สลับเป็น **`userC`** → **เซ็นเอกสาร** → กดเซ็นแทนผู้เกี่ยวข้องคนอื่นจนครบ → สถานะไปที่ **รอ QC ขึ้นทะเบียน** อัตโนมัติ
6. สลับเป็น **`userD`** (QC) → **ขึ้นทะเบียนเอกสาร** → ระบบลงลายเซ็นเจ้าหน้าที่และผู้จัดการ QC ในส่วนที่ 6 ให้เอง → สถานะ **ขึ้นทะเบียนแล้ว** จบ flow
7. กด **จำลองเวลา +1 วัน** ที่แถบดำมุมซ้ายล่างซ้ำ ๆ → เอกสารที่ยังลงนามไม่ครบเมื่อครบ 14 วันจะถูก **ส่งกลับอัตโนมัติ**
8. กดปุ่ม **TH / EN** มุมขวาบนเพื่อสลับภาษาได้ทุกหน้า

**รีเซ็ตข้อมูล** ได้จากแถบดำมุมซ้ายล่าง หรือลิงก์ล่างสุดของหน้า Login

## หมายเหตุสำหรับการพัฒนาต่อ

- **ไฟล์แนบเก็บไฟล์จริง** เป็น data URL ใน localStorage เปิดดู/ดาวน์โหลดได้จากหน้าเอกสาร
  (PDF และรูปภาพแสดง preview เต็ม · ไฟล์ Office แสดงปุ่มดาวน์โหลด)
  มีเพดาน **3.5 MB** ต่อทั้งระบบ เกินแล้วจะเก็บเฉพาะชื่อไฟล์และขึ้นป้าย `name only`
- **ลายเซ็นที่วาดในส่วนที่ 5** ถูกบันทึกเป็นภาพลงเอกสารจริง และแสดงบนหน้า PDF
- วันที่ในระบบใช้ **วันจำลอง (D+n / D−n)** ไม่ใช่วันที่จริง เพื่อให้สาธิตกติกา 7–14 วันได้ในไม่กี่คลิก
- ปุ่ม **พิมพ์ / บันทึก PDF** ในหน้าเอกสารใช้ `window.print()` ของเบราว์เซอร์ (เลือก "Save as PDF")
- เมื่อจะต่อ backend จริง: แทนที่เฉพาะฟังก์ชันใน `js/store.js` ด้วย API calls — หน้าอื่นไม่ต้องแก้
